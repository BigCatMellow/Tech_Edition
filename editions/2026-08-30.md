# Tech Edition

**August 30, 2026**

*Spyro is being ported with a hybrid of matching decompilation and static recompilation, agent reliability is being measured across an operational lifetime, and small tools are learning to observe agent work without scraping the screen.*

## Lead Stories

### OpenPete does not wait for a perfect decompilation before making Spyro native

**New · Project · Usable**

OpenPete is a native PC port of the original *Spyro the Dragon* that combines matched C from the ongoing decompilation with statically recompiled MIPS code for everything not yet recovered. Version 0.1.4 shipped August 17; Windows builds are published and Linux already builds from source.

**Why it matters:** It turns preservation into an incremental pipeline. Verified source can replace translated binary function by function, so a usable port can exist years before a 100% matching decompilation.

The mechanism is unusually clean: recovered functions are compiled from reconstructed source, while unrecovered functions are generated from the original PlayStation instructions by PSXRecomp. Both meet at the same runtime boundary, so the project can gradually exchange translated blocks for verified source without rebuilding the whole architecture.

OpenPete also keeps the original simulation near 29.913 Hz and interpolates additional visual frames rather than simply running the game logic faster. That distinction matters because display smoothness and simulation timing are not the same thing.

Source: https://www.openpete.com/

### AgingBench treats an AI agent like a system that can decay after deployment

**Emerging · Research · Experimental**

AgingBench evaluates agents over repeated sessions instead of only from a clean start. It separates four kinds of long-term degradation: compression, interference, revision, and maintenance.

**Why it matters:** A persistent agent can pass a day-one benchmark and still become less reliable as memory gets summarized, similar facts pile up, old truths are revised, or maintenance operations rewrite stored state.

The useful idea is diagnostic rather than another leaderboard number. A wrong answer caused by information being lost during compaction is a different failure from one caused by retrieval selecting the wrong memory, and both require different repairs. The project supports Claude Code, Codex, OpenHands, Cursor, and custom memory policies, and uses an AgingCard representation to describe failures across controlled tests and supported traces.

Source: https://github.com/VITA-Group/AgingBench

### umux watches agent completion signals instead of guessing from the screen

**New · Tool · Usable**

umux is a terminal workspace manager with tabs, split panels, session restoration, SSH panels, and desktop notifications. Its agent-aware feature listens for OSC terminal control sequences emitted by tools such as Claude Code, Codex, Gemini CLI, and Aider.

**Why it matters:** This is a small but useful observability pattern. Instead of searching visible terminal text for words such as “done” or repeatedly polling a process, umux consumes an explicit machine-readable completion event.

A stateful parser recognizes OSC 9;9, OSC 99, and OSC 777 sequences while passing ordinary terminal bytes through unchanged. The mechanism is old terminal infrastructure being reused as a lightweight event channel for modern agents.

Source: https://github.com/CrystalPlatforms/umux

### A tiny ESP32 can train its own vision model instead of sending images to a cloud

**Emerging · Research · Experimental**

A research prototype trains and runs a small convolutional neural network entirely on an ESP32-S3-class microcontroller with 8 MB of PSRAM. The implementation is about 1,750 lines of C++ and does not depend on a large machine-learning framework.

**Why it matters:** TinyML usually means training on a larger computer and deploying only inference to the device. This project keeps data capture, optimization, weight storage, and inference on the microcontroller itself.

The demonstrated task is deliberately small: 64×64 images and a compact two-layer network. Reported training takes roughly nine minutes and inference reaches about 6.3 frames per second. The value is not state-of-the-art vision; it is that the entire learning mechanism is small enough to inspect.

Source: https://arxiv.org/abs/2604.23012

## GitHub Finds

### PSXRecomp turns unfinished PlayStation decompilations into runnable host code

PSXRecomp translates retail PlayStation MIPS instructions into C ahead of time. A preservation project can therefore run functions that have not yet been manually reconstructed, then replace them as matching decompilation progresses.

**Maturity:** usable  
**Why it matters:** It creates an incremental bridge between opaque binary and verified source instead of forcing a port to wait for complete decompilation.

Source: https://github.com/mstan/psxrecomp

### Flux treats file-manager responsiveness as an architecture problem

Flux is a young Rust/GTK4 Linux file manager. It pushes directory loading, thumbnails, archive access, content search, remote GVFS paths, and file operations through asynchronous paths rather than blocking the interface. The repository also advertises 350+ tests and parser fuzzing.

It can browse archives as virtual filesystems, inspect file metadata, search file contents, connect to remote storage, and synchronize an integrated terminal with the current directory.

**Maturity:** experiment  
**Caveat:** The project is only at 0.1.x, and its startup-speed figures are project-authored rather than independent benchmarks.

Source: https://github.com/killown/flux

### AgingBench uses one diagnostic vocabulary for tests and traces

AgingBench's AgingCard idea is worth studying independently of its benchmark scores: the same failure description can be used in controlled evaluation and supported post-hoc trace analysis.

**MAPS connection:** A shared evidence format for pre-deployment tests and real incidents could make reliability regressions easier to compare over time.

Source: https://github.com/VITA-Group/AgingBench

## Agent Lab

### Interesting research: evaluate the lifespan of the harness, not only the model

AgingBench's deeper point is that an unchanged model can become less reliable because the surrounding memory and maintenance system changes over time. Longitudinal testing should therefore exercise compaction, accumulated context, revised facts, and lifecycle maintenance rather than repeatedly testing a clean agent.

**Classification:** Experiment

umux demonstrates a simple rule for agent observability: when a worker can emit an explicit completion or attention event, consume that signal instead of inferring state from screen content.

**Classification:** Study

The ESP32 vision prototype includes the learning loop rather than treating the board as an inference-only endpoint. That matters for devices that may need to adapt while disconnected or keep training data local.

## How Did They Do That?

### How OpenPete mixes decompilation and recompilation without running two games

Both paths end in host-callable code behind the same runtime boundary. A recovered function is compiled from matching reconstructed source. An unrecovered function is generated from the retail MIPS instructions. Calls can cross between them normally.

That means a translated function can be replaced later by matching source without changing the rest of the port. The preservation project becomes continuously runnable while its evidentiary quality improves piece by piece.

Source: https://www.openpete.com/

## Research Worth Watching

### Agent aging may be more useful than another single-number benchmark

Separating compression, interference, revision, and maintenance failures makes the benchmark useful as a framework for thinking about long-lived systems even if its exact scores do not generalize to every deployment.

**Limitation:** Any “half-life” for an agent will depend heavily on the tested tasks, memory policy, context budget, and maintenance behavior.

Source: https://arxiv.org/abs/2605.26302

### A wearable ring exposes the verification problem in screenless agent interfaces

A CHI 2026 Microsoft Research prototype used touch and haptic feedback to delegate tasks to agents without a screen. In an exploratory study of 11 people, simple delegation was appealing, but confidence fell for more complex workflows when participants lacked visual or audio evidence of what the agent was doing.

**Why it matters:** Making delegation frictionless can simultaneously make verification harder.

Source: https://www.microsoft.com/en-us/research/publication/ai-at-your-fingertips-wearable-ring-as-a-low-friction-interface-for-agentic-ai/

## Weird Computer Corner

### Someone powered a CHIP-8 computer from a Stirling heat engine

A hobby build couples a tiny Stirling engine to a generator producing roughly 150 milliwatts and budgets that power across an ESP32-C3, a 128×64 OLED, and a keypad. Wi-Fi and Bluetooth are disabled, and the processor drops to 10 MHz while idle. It still runs CHIP-8 software and includes an editor.

The interesting part is not novelty alone. Under an extreme energy constraint, architecture becomes power accounting: simpler virtual machines, low clock rates, tiny displays, and fewer radios suddenly make sense again.

Source: https://www.tomshardware.com/pc-components/case-mods/diy-modder-creates-heat-engine-computing-device-powered-by-a-stirling-engine-80-mhz-processor-operates-on-just-150-milliwatts-of-power

## You Probably Didn't Know You Were Interested In This

### Human-agent interfaces have a verification-bandwidth problem

The wearable-ring research connects interface design to agent governance. The less an interface interrupts you, the less evidence it may provide about what happened. Safe delegation therefore needs enough feedback for the consequence and ambiguity of the action, not merely the smallest possible UI.

### Terminal control codes are a tiny event bus hiding in plain sight

OSC sequences predate coding agents by decades, but umux shows that an old side-band protocol can carry machine-readable status without interfering with human-facing output. Sometimes the clean automation hook already exists below the layer people are currently scraping.

### Extreme power limits can make old virtual machines useful again

CHIP-8 is primitive, but that simplicity becomes an advantage when a physical heat engine provides only a fraction of a watt. Old abstractions can return for engineering reasons entirely separate from nostalgia.

## Mechanisms Worth Studying for MAPS

### Experiment — Longitudinal reliability cards

AgingBench records capability changes over repeated sessions and distinguishes compression, interference, revision, and maintenance failures.

**Worth testing:** Build a small MAPS aging suite that repeats handoffs, compaction, corrections, and maintenance operations, then reports *which stage failed* rather than only whether the final answer passed.

### Study — Explicit worker completion events

umux consumes machine-readable terminal notification events rather than guessing from visible output.

**Worth understanding:** Prefer explicit task-state signals from agents and tools, and preserve those signals as coordination evidence. Inferred state should be the fallback, not the default.

### Study — Verification bandwidth as an authority constraint

The wearable-ring study illustrates a general problem: reducing user interruption can also remove the evidence needed to trust a complex delegated action.

**Worth understanding:** MAPS interfaces should increase visible evidence and confirmation requirements as consequence and ambiguity rise instead of optimizing only for fewer interruptions.
