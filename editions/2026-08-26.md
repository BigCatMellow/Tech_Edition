## Lead Stories

### WebMCP could replace a lot of brittle browser clicking with explicit tools

**New · Standard · Experimental**

The W3C WebMCP draft lets a web page expose structured JavaScript tools to an AI agent. Instead of guessing where to click, an agent can call named operations inside the signed-in page context. Chrome is already experimenting with the API, although the surface is still changing.

**Why it matters:** This shifts browser agents from visual imitation toward explicit capabilities. The interesting problem becomes which operations a site chooses to expose, which are read-only, and which require confirmation.

Source: https://webmachinelearning.github.io/webmcp/

### Ladybird is becoming a real browser by doing the unglamorous browser work

**Emerging · Project · Experimental**

Ladybird's July work included private browsing, browser profiles, geolocation, WebAudio progress, undo/redo, a faster compositor, and continued migration of style and layout code to Rust. None is a flashy browser feature; together they are the machinery required for a genuinely independent engine.

**Why it matters:** The modern web is dominated by a very small number of engine families. Ladybird is interesting because it is building another engine rather than wrapping Chromium.

Source: https://ladybird.org/newsletter/2026-07-31/

### A four-star repo has turned Vandal Hearts into a byte-checked native PC port

**New · Project · Usable**

VandalHearts-PcPort combines a matching PlayStation decompilation with a native Windows/Linux runtime. Recent commits re-verified byte-exact decomps after an OS reinstall, checked multiple disc regions, rebuilt the Windows target and Linux AppImage, and documented reproducibility traps.

**Why it matters:** This is preservation as engineering rather than emulation alone: first recover a reference that can be checked against the original binary, then keep modern platform work separate from that reference.

Source: https://github.com/HalmyLyseas/VandalHearts-PcPort

### An agent-memory paper asks a better question: which other agents should you trust?

**New · Research · Experimental**

Σ-Mem proposes an online memory for multi-agent systems that records evidence about peer competence and relationships, then uses that history to influence routing and aggregation. The important idea is less "agents remember" than "delegation becomes evidence-based state."

**Why it matters:** Static agent roles assume a worker is equally trustworthy forever. Reliability memory creates a path toward routing based on observed outcomes, while also exposing hard questions about noisy evaluation and correlated mistakes.

Source: https://arxiv.org/abs/2607.27958

## How Did They Do That?

### How matching decompilation turns "looks right" into a byte-level test

A decompiler normally recovers plausible high-level behavior, not original source. Matching-decomp projects reconstruct code, compile it under historical toolchain assumptions, and compare emitted bytes with the original binary until they match.

A mismatch becomes evidence. Perhaps a type width is wrong, a branch is expressed differently, a compiler optimization changed, or a structure layout is off. Contributors change source until the historical compiler emits the target sequence.

This gives preservation projects a deterministic acceptance test. Modern graphics, audio, input, filesystem and packaging work can then live in a separate native-port layer while the matching reconstruction remains a checked reference.

Source: https://www.retroreversing.com/how-decompilers-work

## You Probably Didn't Know You Were Interested In This

### Hedged requests: sometimes the best retry starts before the first attempt fails

Distributed systems sometimes duplicate a slow or risky operation and accept the first good result, reducing the rare very-slow requests that dominate visible latency. The agent connection is deeper than "multi-agent debate": redundancy itself can be a reliability control.

### Materialized views are a surprisingly good mental model for agent memory

Databases often keep durable base records and build faster derived views from them. mom's Ledger-to-Markdown design points toward the same pattern: preserve evidence, derive a task-friendly representation, and rebuild the representation when necessary.

This reframes memory from "where do summaries live?" to **what is authoritative, what is derived, and how do we recover?**

### Energy-harvesting interfaces: a device can be off until interaction powers it

NFC harvesting suggests interfaces with no ordinary idle state. The interaction itself provides energy to wake electronics, receive a command, change persistent state such as e-ink, and disappear again.

That connects e-ink to passive sensors, smart labels, and physical information systems rather than just another reader.
