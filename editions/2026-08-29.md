# Tech Edition

**August 29, 2026**

*Xbox 360 recompilation is turning Blue Dragon into a native PC game, obsolete film scanners are gaining a hardware-verified public protocol reference, and agent-memory research is shifting from “can it store this?” to “can it still use it later?”*

## Lead Stories

### Blue Dragon is escaping the Xbox 360 through static recompilation

**New · Project · Usable**

re:Blue 1.0 rebuilds *Blue Dragon* as a native Windows, Linux and macOS application using the ReXGlue Xbox 360 recompilation toolkit. It supports modern resolutions, unlocked frame rates, native keyboard and mouse, Steam Deck, profiles and a built-in mod manager while requiring the user’s own three retail discs.

**Why it matters:** This is a useful midpoint between emulation and full source decompilation. Original machine code is translated into a host-native program while a runtime layer replaces console services and graphics assumptions.

The project was actively pushed on August 28 and carries a 1.0.0 release bump. The important mechanism is the split between translated game code and reusable compatibility infrastructure.

Source: https://github.com/zolaware/reblue

### A seven-star repository is preserving how discontinued Kodak/Pakon film scanners actually work

**New · Project · Usable**

`pakon-reference` documents the USB protocol, firmware loading, image stream, calibration, color pipeline and film transport of Pakon F-X35 scanners. It ties claims to captures, disassembly, OEM behavior, independent clients and live hardware verification, while unresolved disagreements remain explicitly unresolved.

**Why it matters:** Hardware preservation often fails because every new driver author must rediscover the same undocumented protocol. A neutral reference with provenance can outlive any one application.

Source: https://github.com/alibosworth/pakon-reference

### Agent memory benchmarks are starting to test whether remembered evidence remains useful over time

**New · Research · Experimental**

StreamMemBench evaluates memory systems on time-ordered life streams with paired tasks: first use observed evidence, then incorporate feedback and reuse it later. Its August 26 paper revision reports that systems often store information without reliably using it or carrying correction forward.

**Why it matters:** A memory system can score well on retrieval while failing its actual job: changing later behavior because of earlier evidence and corrections.

Source: https://arxiv.org/abs/2606.14571

### doku.md treats agent-generated Markdown as a reading problem, not another note-taking platform

**Emerging · Tool · Usable**

doku.md is a zero-star desktop documentation browser built around local folders, SQLite FTS5 search, file watching, tabs, bookmarks and automatic reindexing. It is explicitly aimed at repositories accumulating specs, plans and task files.

**Why it matters:** In agent-heavy development, navigation and context recovery can become a larger problem than writing. A read-first browser has a different—and narrower—design target than an editor or knowledge base.

Source: https://github.com/dokumd/doku.md

## GitHub Finds

### ReXGlue is turning Xbox 360 recompilation into reusable infrastructure

ReXGlue provides the runtime and toolkit underneath projects such as re:Blue. The important idea is cumulative platform knowledge: graphics, memory and operating-system assumptions can move into a shared layer instead of being rediscovered for every game.

Source: https://github.com/rexglue/rexglue-sdk

### pakon-reference treats provenance as part of the technical specification

It distinguishes hardware-confirmed facts, cross-confirmation, inference and unresolved disagreement. That evidence model is more interesting than its star count.

Source: https://github.com/alibosworth/pakon-reference

### sklauncher is a tiny terminal launcher that learns from launch history

A Rust utility that fuzzy-searches Linux `.desktop` applications, executables and raw commands, then ranks partly from prior launches. The repository is small and was last pushed in July, but it solves one problem without trying to become a desktop shell.

Source: https://github.com/miyakogi/sklauncher

## Agent Lab

### Interesting research: test memory as use → correction → reuse

StreamMemBench separates evidence recall from initial evidence use, feedback incorporation and later reuse. For MAPS-style systems, this suggests a stronger test than “can the agent retrieve the old note?”: give it a correction, then see whether the correction changes a later recommendation.

### Useful now: isolate parallel coding agents with Git worktrees

Emdash gives each task a separate Git worktree and branch. That provides filesystem isolation using an existing version-control primitive, with review and merge as the reconciliation point. It prevents direct file collisions, though it cannot prevent two agents from making logically incompatible changes.

Source: https://github.com/generalaction/emdash

## Hardware & Tinkering

### A protocol reference can be the missing repair part

For discontinued hardware, a public description of firmware loading, calibration, transport and image formats may be as important as physical replacement parts. Pakon’s old scanners are a good example.

### SB Mini II rebuilds an Apple II+ around parts that are still obtainable

The current community build replaces scarce DRAM with SRAM, omits the original composite-generation circuitry and uses a Raspberry Pi Pico to translate USB keyboard input into the Apple II keyboard matrix. The published how-to is still explicitly a work in progress.

Source: https://www.classic-computing.de/sb-mini-ii-howto/

## How Did They Do That?

### How static recompilation turns a console binary into a native PC program

A recompiler analyzes the original executable and translates its CPU instructions ahead of time into code the host can execute. That translated program is then linked to a compatibility runtime that provides the graphics, memory, filesystem and operating-system behavior the console used to supply.

The important architectural split is **translated game logic versus reusable platform replacement**. When the runtime improves, multiple games can benefit.

Source: https://github.com/rexglue/rexglue-sdk

## Research Worth Watching

### StreamMemBench: can feedback survive into the next task?

The paired-task design makes memory evaluation behavioral rather than purely archival. A correction that gets stored but does not affect the next decision is not useful memory.

Source: https://arxiv.org/abs/2606.14571

### When stored evidence stops being usable

A separate paper keeps relevant evidence fixed while adding irrelevant sessions, then measures when reliability crosses a failure threshold and how many memory calls are required. The useful lesson is that “scales to X memories” is meaningless without specifying the model, retrieval interface, noise and interaction budget.

Source: https://arxiv.org/abs/2605.07313

## You Probably Didn't Know You Were Interested In This

### Reverse-engineered documentation can itself be the preservation artifact

The Pakon project is interesting even without owning a film scanner. It preserves *how we know* what a machine does, separating evidence, confidence and implementation. That connects hardware hacking with archival practice and scientific reproducibility.

### CRDTs are what make offline edits that later merge more than a sync slogan

Conflict-free replicated data types let multiple copies accept edits independently and later converge without a central lockstep transaction. The mechanism sits underneath collaborative documents, offline-first apps and distributed state—two steps away from personal knowledge tools but directly relevant to resilient shared systems.

Source: https://arxiv.org/abs/2605.31569

## Mechanisms Worth Studying for MAPS

### Study — Evidence-status labels instead of flat truth

Pakon’s reference distinguishes hardware-confirmed facts, cross-confirmation, inference and unresolved disagreement. MAPS support documents could similarly carry claim-level authority and provenance rather than forcing every statement into the same confidence class.

### Experiment — Correction-follow-up evaluation

StreamMemBench tests whether feedback changes later behavior. A useful MAPS test would give the system a known correction, then require a later handoff or recommendation to reflect it.

### Experiment — Worktree isolation for parallel mutable work

Separate Git worktrees provide a cheap sandbox boundary: each agent changes its own filesystem and branch; differences reunify only through explicit review and merge.
